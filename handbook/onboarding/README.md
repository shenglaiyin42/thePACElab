# PaceLab 新成员入组指南

## 欢迎加入 PaceLab

欢迎加入 PaceLab！很高兴你来到这里，和我们一起开始接下来的学习与研究。

刚加入一个新的团队，总会有一些需要慢慢熟悉的事情。这份指南整理了课题组的基本信息、日常工作方式，以及入组初期需要完成的事项。你不必一开始就记住所有内容；遇到不清楚的地方，随时提出来就好。

## 1. 关于 PaceLab

PaceLab 的全称是 **Pathogen Dynamics, Animal Movement, Global Changes, and Ecology Lab**。我们关注病原体动态、动物移动、全球变化与生态过程之间的联系。

目前，课题组的工作主要以数据分析和模型建模为主。未来随着研究项目的发展，我们也可能开展一些野外工作。

## 2. 日常沟通

课题组内部与工作有关的沟通统一使用电子邮箱。任务安排、材料发送、进度更新，以及需要进一步确认的问题，都通过邮件进行。这样既方便大家在合适的时间集中处理，也能把重要信息记录并保存下来，之后需要时可以随时查找。

与课题组外的人员沟通时，可以根据对方的习惯和实际情况，灵活选择合适的沟通方式。

如果遇到比较紧急、无法等待邮件回复的情况，可以通过电话、短信或微信联系。具体联系方式会在入组后另行提供。

### 组内例会

每位成员都应积极、负责地参加组内例会，并主动参与讨论。具体的组会内容和安排会根据每学期的实际情况确定。

### 日历与会议安排

每位成员都应尽快熟悉并掌握日历系统的使用。组内的工作会议、重要时间节点和其他相关安排，都应及时加入自己的日历，并同步到电脑和手机等移动设备，以便随时查看和更新。

如果需要在已经固定安排的组内例会或个人例会之外，单独与老师安排会议，请通过邮件提出，并在邮件中写明希望讨论的事项和期望的会议时间。

## 3. 工作邮箱

加入课题组后，每位成员都需要自行申请一个 Outlook 邮箱，作为在组内开展工作的主要邮箱。

邮箱名称统一采用以下格式：

```text
名.姓42@outlook.com
```

这里的姓名使用汉语拼音，并按照“名在前、姓在后”的顺序填写。例如，李雷的邮箱应为：

```text
lei.li42@outlook.com
```

申请完成后，请先测试邮箱能否正常收发邮件，并将这个地址告知课题组。

### 账号安全

- 使用独立且强度足够的密码；
- 如服务支持，请开启双因素认证；
- 设置可靠的账号恢复方式；
- 不要与他人共享密码或验证码；
- 不要使用临时邮箱注册重要科研服务。

## 4. GitHub 与代码管理

每位成员都需要注册自己的 GitHub 账号，并尽快熟悉 GitHub 的基本使用方法。刚开始不熟悉很正常，但希望大家能够在实际工作中逐步掌握，并养成规范使用的习惯。遇到不确定的操作时，可以先问清楚再进行。

GitHub 是课题组代码管理的中枢。在组内工作中产生的代码，都应同步到课题组指定的 GitHub 仓库中。重要的修改过程、阶段版本和最终版本也应通过 GitHub 留下记录，而不是只保存在个人电脑里。

课题组代码默认不对外公开。未经许可，不要将与组内工作有关的代码发送给第三方、上传到公开仓库，或放到其他未经批准的平台上。在新建仓库或调整访问权限前，也请先确认相关要求。

## 5. AI 工具的使用

课题组不禁止使用 AI 工具，但每个人都需要负责任地使用。AI 可以帮助我们完成工作，却不能替使用者承担责任。对于 AI 生成或参与生成的内容，使用者需要进行必要的事实核查、准确性验证和完整审阅，并对最终使用或提交的结果负全部责任。

### 代码编写

原则上鼓励大家合理使用 vibe coding 的方式辅助编写代码。无论代码以何种方式生成，使用者都需要理解代码的内容和运行逻辑，并在整个过程中提供详细、明确且准确的标注与解释。

所有与组内工作有关的代码，都应完整同步到课题组指定的 GitHub 仓库，让组内成员能够查看代码、修改记录和相关说明。

### 文字处理

使用 AI 生成、修改或润色文字时，使用者必须完整检查其中的事实、数据、逻辑和表述。任何由使用者提交、发送或发布的文字，无论 AI 参与了多少，都由使用者本人负全部责任。

### 订阅费用

AI 工具的订阅费用现阶段由补助金覆盖。后续会根据经费安排和实际使用情况作相应调整。

## 6. 个人资料与网站信息

每位成员需要提交一张标准的大头照，以及一份简短的个人介绍，用于更新课题组网站。

照片应清晰、自然，背景尽量简洁，并提交清晰度足够的原始文件。个人介绍可以包括自己的学习或研究经历、研究兴趣、常用方法，以及目前希望开展的工作。文字不需要很长，重点是让别人能够比较自然地了解你和你的研究。

具体内容和呈现方式可以参考 [PaceLab 官方网站的成员页面](https://thepacelab.org/people.html)。如有 ORCID、Google Scholar 或其他希望展示的学术主页，也可以一并提供。提交前请确认这些信息适合在公开网站上展示。

## 7. 数据与文件存储

数据分析和模型建模工作应尽量做到过程清晰、结果可追溯。

在找到安全、合适的云端存储方案之前，课题组的数据、数据文档、文本及其他工作文件统一使用移动硬盘存储，不使用百度网盘或其他类似的云盘服务进行组内存储和分享。代码仍按照前文的要求，保存在课题组指定的 GitHub 仓库中。

如果需要移动硬盘，或者电脑本身的存储空间不够，可以向老师提出申请。

与组外合作者沟通时，如果对方使用百度网盘等服务，可以根据实际情况灵活配合；但这些服务不能作为课题组内部保存、整理或日常分享数据的空间。

基本要求包括：

- 保存原始数据，不直接覆盖；
- 记录数据处理、模型设置和主要修改；
- 重要文件不应只保存在个人电脑中；
- 按课题组约定的位置保存和备份数据与文档；
- 不将敏感或未公开资料上传到未经允许的公共平台。

具体的文件命名、目录结构、备份方式和代码管理规则将在后续版本中补充。

## 8. 办公用品与电子配件

如果工作中需要办公用品或电子配件，请通过邮件向老师说明具体情况。邮件中可以简单写清楚需要的物品、用途和时间要求，方便后续确认和安排。

## 9. 野外工作

如参与野外工作，成员需要在出发前了解任务内容、时间安排、所需装备和安全要求。

未经必要说明或培训，不应独立开展存在安全风险的工作。具体要求将根据项目地点和任务类型另行提供。

## 10. 入组首周清单

- [ ] 确认主要指导人和日常联系人
- [ ] 加入课题组的沟通与协作平台
- [ ] 确认中英文姓名及学术署名
- [ ] 注册并测试工作邮箱
- [ ] 完成邮箱安全设置
- [ ] 将工作日历同步到电脑和手机等移动设备
- [ ] 注册 GitHub 账号并将用户名告知课题组
- [ ] 加入指定的 GitHub 仓库，了解基本的代码同步流程
- [ ] 提交标准大头照和个人简介
- [ ] 获取所需的数据、代码和共享文件访问权限
- [ ] 确认移动硬盘和电脑存储空间是否满足工作需要
- [ ] 了解组会和日常沟通安排
- [ ] 与指导人确认第一阶段的学习或研究任务

## 11. 需要帮助时

新人不需要在入组时立即熟悉所有流程。遇到账号、数据、研究任务、野外安全或团队协作方面的问题，请及时联系指导人或指定联系人。

如果现有说明不够清楚，也欢迎提出建议，帮助我们共同完善这份指南。
